## 2. Implemented Server Features

### Execution Modes

```
./DMC --server    # gRPC server mode, listens for client connections
./DMC --client    # gRPC client mode, connects to a remote server
./DMC --local     # Local interactive mode, direct console operation (no network required)
```

### Core Features

| Feature | Description |
|---------|-------------|
| Register | Register any type of Data Element (e.g. Car, Person, Animal) without code changes |
| Update | Update an existing Data Element |
| Print | Print a single Data Element (via IPrintable interface, server does not need to know the concrete type) |
| PrintAll | Print all objects currently in the system |
| GetKey | Each element determines its own unique key (via IKeyIdentifiable interface) |
| Singleton | All client connections share the same data pool |

### gRPC Service (Implemented, Pending Verification)

| RPC Method | Type | Description |
|-----------|------|-------------|
| Register | Unary | Register a single Data Element |
| Update | Unary | Update a Data Element |
| Print | Unary | Query a single element's display string |
| PrintAll | Server Streaming | Stream all elements back to the client |
| BatchRegister | Client Streaming | Client sends multiple elements in batch |
| GetCount | Unary | Query the number of elements in the system |
| Contains | Unary | Check whether an element exists |

### Technical Architecture

```
Client (gRPC / Console)
    ↓
DMCCore (C# — Singleton Server + gRPC Service)
    ↓
Bridge (P/Invoke — C# calls C++)
    ↓
HardwareLogic (C++17 — libHardwareLogic.so)
```

## 3. How to Obtain the Project

### Option A: Clone from GitHub

```bash
git clone https://github.com/kaijaytu/Data-Management-Capability-DMC.git
cd Data-Management-Capability-DMC
git checkout develop    # Main development branch
```

### Option B: Restore from Archive

After receiving the archive:

```bash
tar -xzf DMC-full.tar.gz
cd Data-Management-Capability
git log --oneline       # Verify commit history is intact
git checkout develop
```

## 4. Build and Run on RHEL 9.2

### First-Time Environment Setup (as root)

```bash
su - root
cd /path/to/Data-Management-Capability
chmod +x scripts/pipeline_*.sh scripts/setup/*.sh scripts/build/*.sh scripts/deploy/*.sh
./scripts/pipeline_install.sh    # Install .NET SDK, CMake, GCC
exit
```

### One-Click Build + Deploy + Run (as user)

```bash
./scripts/pipeline_start.sh
# Automatically executes: Build (C++ + C#) → Deploy (/opt/dmc) → Start Server
# The deploy step will prompt for the root password
```

### Manual Start

```bash
# Local mode (direct operation)
/opt/dmc/DMC --local

# gRPC mode (Server + Client)
# Terminal 1:
/opt/dmc/DMC --server --port 5000

# Terminal 2:
/opt/dmc/DMC --client --address http://localhost:5000
```

### Clean Up and Restore (as user)

```bash
./scripts/pipeline_stop.sh       # Undeploy + clean build artifacts
```

### Remove Environment (as root)

```bash
su - root
./scripts/pipeline_uninstall.sh  # Only removes dependencies installed by this project
```

## 5. Development on Windows

```bat
REM Install .NET SDK (as Administrator)
scripts\setup\install_deps.bat

REM Build C# (as regular user)
scripts\build\build.bat

REM Clean build artifacts
scripts\build\clean.bat
```

Note: Windows only compiles the C# portion for syntax checking. Full builds (including C++ HardwareLogic) must be performed on RHEL.
